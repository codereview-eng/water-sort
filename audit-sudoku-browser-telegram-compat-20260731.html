Executive verdict

浏览器：有条件可运行
Telegram：未达到生产直发

页面采用原生 HTML/CSS/JavaScript，核心游戏、存储、国际化和网络失败降级逻辑齐全，适合现代浏览器静态托管。但当前发布说明遗漏本地 SDK 文件，广告 SDK 会同步阻塞首屏；Telegram 身份只在客户端解析且排行榜允许公共整包写入，因此不能把现状定义为“安全、可直接上线的 Mini App”。

普通浏览器

通过 HTTP/HTTPS 静态托管，核心游戏路径具备运行基础。外部广告、国家识别、排行榜失败时大多有降级。

本地双击

不建议作为正式运行方式。页面包含跨域请求和外部脚本，file:// 行为因浏览器策略而异。

Telegram

SDK、ready/expand、主题、触觉、CloudStorage 与分享桥已接入；仍缺真实 HTTPS/BotFather/客户端验收和可信后端。

发布阻断与主要风险

按用户影响和可被利用程度排序。高优先级项未处理前，不建议把排行榜、账号身份或奖励资产当作可信生产数据。

HIGH 01

Telegram 身份可由客户端 Hash 伪造，未做服务端校验

页面直接读取 SDK 的 initDataUnsafe.user，SDK 不可用时又从 URL Hash 解出用户信息。两条路径都只用于客户端显示，没有把原始 initData 发到服务端按 Telegram 签名验证。

sudoku.html:520sudoku.html:527sudoku.html:533tgid.js:16

影响：攻击者可构造 Hash 冒充任意 Telegram 用户。官方文档明确要求：可信数据应使用 initData 在服务端验证，不能信任 initDataUnsafe。最小修复是增加后端验证端点、校验签名与 auth_date，再签发短会话。

HIGH 02

共享排行榜是公共整包读改写，存在篡改与覆盖风险

浏览器先读取公共 JSON Blob，修改自己的条目后再把整个对象 PUT 回去。该模式没有授权、原子更新、版本冲突控制或服务端单调递增校验。

sudoku.html:1000sudoku.html:1188sudoku.html:1193sudoku.html:1199

影响：任何能调用该地址的人都可能改分、删榜或覆盖并发提交。最小修复是改为后端 POST /score：验证 Telegram 会话、只接受合法关卡结果、仅提升个人最高分，并由服务端生成榜单快照。

MED 03

广告 SDK 在 Head 中同步加载，弱网时可能阻塞首屏

libtl.com/sdk.js 没有 async 或 defer，位于正文之前。虽然业务函数提供 1.2 秒演示模式，但只有脚本加载完成或失败后，浏览器才会继续解析到该降级逻辑。

sudoku.html:12sudoku.html:777sudoku.html:781

影响：广告域名慢、被拦截或 DNS 异常时，用户可能长时间看到空白页。审计中的 Chrome CLI 也在此类网络任务下未能及时结束，但该现象只作为风险信号，不作为页面必然失败的证明。建议异步动态加载，并设置超时后直接进入演示/无广告路径。

MED 04

“单文件上传”手册与实际依赖不一致

手册要求只上传并重命名 sudoku.html，页面却先加载同目录的 tg-web-app.js。漏传时会回退 Telegram 官方 CDN，但这会丢失仓库原本为受限网络准备的同源 SDK 保障。

manual-launch.html:57manual-launch.html:59sudoku.html:7sudoku.html:10

影响：按手册逐字操作不能得到与仓库一致的运行环境。应明确发布清单至少包含 index.html 与 tg-web-app.js，或把 SDK 真正内联进单文件。

MED 05

仓库没有可复现部署入口，手册分支名也与当前仓库不符

根目录未发现 package、README、Pages workflow、Vercel/Netlify/Cloudflare 配置；当前 Git 分支为 master，手册却写固定选择 main。

manual-launch.html:60git branch: master根目录：无部署配置

影响：新人按步骤发布时容易选错分支，也无法从仓库本身复现部署和回滚。至少应增加 README、明确完整文件清单与实际分支；更稳妥的是提供自动部署工作流。

LOW 06

现有 UI 测试不是浏览器或 Telegram 端到端测试

UI 测试从 HTML 正则截取函数，在 Node vm 中执行，并用文本匹配验证 DOM 代码存在。它能防止部分逻辑回归，但不会执行完整 HTML、资源加载、真实事件、存储、CORS 或 Telegram SDK 生命周期。

sudoku-ui.test.js:6sudoku-ui.test.js:9sudoku-ui.test.js:31sudoku-ui.test.js:67

影响：79 项测试全绿仍不能证明“浏览器可打开”或“Telegram 可启动”。应补最小 Playwright/WebDriver smoke 与真实 Telegram 客户端验收。

运行环境判定矩阵

“可运行”与“可生产使用”分开判断，避免把演示成功误当作发布完成。

场景判定核心能力剩余条件
现代 Chrome / Edge，HTTP(S) 静态托管有条件通过核心游戏、localStorage、键盘/触摸、网络失败降级将广告 SDK 改为非阻塞；做一次真实浏览器 smoke
现代 Safari / Firefox，HTTP(S) 静态托管高概率可用，未实测所用 API 大多为现代标准能力补跨浏览器 E2E；关注媒体查询监听与存储策略差异
直接双击 file://不作为支持口径本地脚本和核心逻辑可能工作跨域 fetch、外部脚本、存储源策略不可控；改用本地静态服务器
Telegram 测试环境集成基础已具备SDK、身份展示、主题、触觉、CloudStorage、分享真实 HTTPS URL、BotFather 配置、移动端 Telegram 验收
Telegram 生产环境暂不建议前端体验基本完整服务端验证 initData；替换公共排行榜写入；监控外部脚本失败

最小实施顺序

先处理会阻塞首屏和污染生产数据的事项，再补自动化与发布便利性。

1

解除首屏阻塞

  • 把 Monetag SDK 改成 async 或页面启动后动态加载。
  • 设置明确超时；失败时直接维持演示/无广告模式。
  • 验收：屏蔽 libtl.com 后首页仍在 2 秒内可交互。
2

建立可信身份

  • 把 TG.initData 发给后端验证。
  • 校验签名、auth_date 与重放窗口。
  • 前端 Hash 解析只作为展示降级，不再作为授权依据。
3

替换公共排行榜写入

  • 客户端只提交本次成绩，不再 GET 后整包 PUT。
  • 后端原子更新个人最高成绩并限流。
  • 验收：并发提交不会丢记录，伪造用户无法改榜。
4

对齐发布说明

  • 说明必须上传 tg-web-app.js，或真正内联。
  • 把固定 main 改为“选择实际发布分支”，当前仓库为 master。
  • 增加 README 与可复现部署配置。
5

补自动化 Smoke

  • 浏览器：首屏、开局、输入、返回、语言、持久化。
  • 故障注入：SDK、广告、排行榜、IP 服务全部失败。
  • Telegram mock：ready/expand、主题、CloudStorage、分享。
6

完成真实客户端验收

  • 部署公开 HTTPS URL 并配置 BotFather。
  • 至少覆盖 Android、iOS、Desktop 三端 Telegram。
  • 记录冷启动、返回手势、主题切换、断网与分享结果。

建议的发布验收口径

全部满足后，才把状态从“有条件可运行”提升为“可直接发布”。

门槛通过标准证据形式
普通浏览器Chrome、Safari、Firefox 首屏与开局无未捕获异常；第三方域名全阻断仍可玩E2E 运行记录 + 控制台零异常
页面性能广告域名无响应时不阻塞 HTML 解析；首页 2 秒内可交互网络故障注入结果
Telegram 启动真实 BotFather 深链在 Android/iOS/Desktop 打开，ready 后页面稳定三端测试清单或录像
身份安全伪造 Hash、篡改 initData、过期 auth_date 均被服务端拒绝后端安全测试
排行榜完整性未认证请求不能写；并发提交不覆盖；成绩只能合法递增API 集成与并发测试
发布可复现新环境按 README 一次完成部署，文件清单、分支、URL 和回滚步骤明确干净环境发布记录
